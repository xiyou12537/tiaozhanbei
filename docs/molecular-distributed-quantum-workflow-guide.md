# 分子量子分布式计算平台：系统目标、工作原理与操作指南

## 1. 文档目的

本文档用于说明当前“分子量子分布式计算平台”解决的具体应用问题、采用的技术方案、用户操作流程，以及工作流中各阶段和结果字段的含义。

本文只描述当前统一小分子 Workflow，不包含已经从新版产品中隔离的锂硫电池、材料筛选和旧平台工作流。

## 2. 系统一句话定位

本系统将固定几何下的小分子电子基态能量问题转换为量子线路，再根据多颗虚拟量子芯片的容量和拓扑约束完成线路分区、节点映射、芯片内 SWAP 路由和逻辑分布式模拟，最后验证分布式执行是否保持原线路的能量结果。

完整链路为：

```text
分子结构
-> 经典电子结构计算
-> 费米子 Hamiltonian
-> Qubit Hamiltonian
-> VQE 参数化量子线路
-> 线路分区
-> 虚拟 QPU 映射
-> 芯片内拓扑路由
-> 逻辑分布式模拟
-> 能量一致性验证
```

系统当前是面向分子量子计算的分布式编译、路由与模拟验证平台，不是真实量子计算机云平台，也不是已经实现量子加速的工业化计算化学平台。

## 3. 系统解决的具体应用问题

### 3.1 分子结构不能直接交给量子计算机

用户能够描述的是原子种类、三维坐标、电荷和自旋，但量子线路需要 Qubit、量子门和可测量算符。系统负责完成从化学问题到量子计算问题的转换：

```text
元素与坐标
-> 分子轨道和电子积分
-> 电子相互作用 Hamiltonian
-> Pauli 算符
-> X、RY、CX 量子线路
```

### 3.2 为什么需要计算分子能量

分子能量是计算化学中最基础的量之一。实际应用通常不关心一个孤立的绝对能量，而关心相同计算条件下不同状态之间的能量差。

典型应用包括：

| 应用问题 | 常用能量关系 | 能说明什么 |
| --- | --- | --- |
| 稳定构型比较 | `E_A - E_B` | 哪个构型在电子能量层面更稳定 |
| 键长和几何优化 | 不同坐标下的 `E(R)` | 势能面最低点和稳定几何 |
| 反应能 | `E_products - E_reactants` | 反应在电子能量层面吸热或放热 |
| 结合能 | `E_AB - E_A - E_B` | 两个体系是否倾向于结合 |
| 活化能 | `E_transition - E_reactants` | 反应需要跨越的能垒 |
| 原子受力 | 能量对坐标的导数 | 几何优化和分子动力学的运动方向 |

当前 Workflow 只计算一个固定几何下的近似电子基态能量。它尚未自动执行几何优化、构型扫描、过渡态搜索、热力学校正、溶剂效应或激发态计算。

因此，当前系统的直接目标不是给出完整化学结论，而是验证分子能量量子线路经过分区和路由后能否保持计算语义。

### 3.3 为什么需要量子计算表示

分子中的电子存在量子叠加、反对称性和电子关联。随着活性电子和轨道增加，精确描述所有电子组态的经典计算成本可能快速增长。

量子计算的长期目标是使用 Qubit 表示电子量子态，并通过量子线路求解分子 Hamiltonian 的低能态。当前系统使用 VQE 作为小规模演示算法，通过参数化线路制备候选量子态，再由经典优化器搜索较低能量。

### 3.4 为什么考虑分布式量子执行

单颗量子芯片受到两类限制：

1. 可用物理 Qubit 数量有限；
2. 芯片内部的 Qubit 不能任意两两直接执行双比特门。

当线路规模超过单颗芯片容量时，需要研究如何把线路拆到多颗芯片上，以及如何处理芯片内路由和芯片间通信。本系统针对这一问题验证：

- 逻辑 Qubit 如何划分为多个分区；
- 每个分区映射到哪颗虚拟 QPU；
- 非相邻双比特门如何通过 SWAP 路由；
- 哪些门跨越不同虚拟 QPU；
- 分布式执行后能量是否仍与原线路一致。

## 4. 系统如何解决问题

系统使用三条相互衔接但含义不同的计算链路。

### 4.1 经典电子结构计算

后端通过 Docker 运行 PySCF，根据分子几何、电荷、自旋和基组执行 Hartree-Fock 自洽场计算，得到：

- 分子轨道；
- 轨道能量和占据数；
- 一电子积分；
- 二电子积分；
- HF 总能量；
- 可选活性空间候选。

这些结果的作用不是相同的：

- **分子轨道**决定哪些电子自由度适合进入活性空间；
- **电子积分**定义电子动能、核吸引和电子排斥的强度，是构造 Hamiltonian 的系数来源；
- **HF 能量**是经典平均场近似结果，也是 VQE 初态和计算合理性的参考。

电子积分用于构造费米子 Hamiltonian：

```text
H = sum(h_pq * a_p^† * a_q)
  + 1/2 * sum(h_pqrs * a_p^† * a_q^† * a_r * a_s)
  + E_core
```

随后使用 Jordan-Wigner 映射将其转换为 Qubit Hamiltonian：

```text
H = sum(c_i * P_i)
```

其中 `P_i` 是由 `I、X、Y、Z` 组成的 Pauli 字符串，`c_i` 是对应系数。

### 4.2 未分区 VQE 状态向量模拟

系统内置了面向当前 `X、RY、CX` Ansatz 的 NumPy 状态向量模拟器。

对于 `n` 个 Qubit，模拟器保存 `2^n` 个复数振幅。它按顺序将每个量子门对应的矩阵作用到状态向量，再计算每个 Pauli 项的期望值：

```text
<P_i> = <psi|P_i|psi>
E(theta) = sum(c_i * <P_i>)
```

VQE 的工作循环为：

```text
给定参数 theta
-> 执行 X、RY(theta)、CX 线路
-> 计算 Pauli 期望值和能量
-> Powell 优化器更新 theta
-> 重复直到优化器终止
```

优化完成后，参数被替换为具体角度，系统输出可执行的 OpenQASM 2.0 线路。

当前使用精确状态向量期望值，不进行真实 QPU 测量，也不模拟随机 shot 噪声。请求中虽然保留 `shots` 字段，但当前能量不由随机采样得到。

### 4.3 路由后的逻辑分布式模拟

VQE 线路经过分区、虚拟节点映射和芯片拓扑路由后，会生成全局有序的 `routed_execution_plan`。逻辑分布式模拟器实际消费该计划，而不是复用未分区 VQE 的最终能量。

模拟器会：

1. 根据分区和虚拟 QPU 映射确定状态张量轴顺序；
2. 逐步执行计划中的 `X、RY、CX、SWAP`；
3. 校验每一步执行前后的 logical-to-physical 布局；
4. 校验芯片内 CX 是否位于合法物理耦合边上；
5. 对跨分区 CX 记录通信事件；
6. 从最终状态重新计算全部 Pauli 期望值和能量；
7. 与未分区 VQE 能量比较。

当前 SWAP 通过更新逻辑 Qubit 到物理 Qubit 的布局关系进行跟踪。后续门必须按更新后的布局解析，因此删除必要 SWAP 或篡改布局会导致执行计划校验失败。

## 5. 用户如何操作系统

### 5.1 注册与登录

用户需要先注册并登录。当前注册约束为：

- 用户名长度为 2 至 50 个字符；
- 密码长度为 6 至 100 个字符。

Workflow、详情和历史记录按当前 Bearer 用户隔离。

### 5.2 进入新建计算页面

登录后进入：

```text
/app/molecules
```

页面首先读取后端 `GET /api/molecule-workflows/capabilities`，使用服务端声明的元素、基组、原子数、Qubit 数、分区和路由能力生成表单。

### 5.3 第一步：分子与几何

用户可以选择 H2、LiH、H2O 预置，也可以编辑原子列表。

| 字段 | 含义 | 对计算的影响 |
| --- | --- | --- |
| 分子名称 | Workflow 中的识别名称 | 用于任务检索和展示，不直接参与物理计算 |
| 元素 | 原子的化学元素 | 决定核电荷和电子数量 |
| X/Y/Z 坐标 | 原子三维位置，单位为 Angstrom | 决定核间距离、轨道和电子积分 |
| 总电荷 | 体系相对中性状态多出或缺少的电子 | 改变电子总数 |
| 自旋多重度 | `2S + 1` | 决定闭壳层或开壳层电子结构处理 |
| 基组 | 表示电子轨道的数学函数集合 | 影响精度、轨道数量和计算成本 |

当前几何按原样提交，不执行几何优化。用户输入的每一组坐标代表势能面上的一个固定点。

### 5.4 第二步：电子结构与 VQE 参数

| 字段 | 含义 | 主要权衡 |
| --- | --- | --- |
| 活性空间轨道数 | 进入量子 Hamiltonian 的关键空间轨道数量 | 越大越可能保留更多电子关联，但需要更多 Qubit |
| Pauli 截断阈值 | 删除绝对系数低于阈值的 Pauli 项 | 阈值越大线路和测量更简单，但近似误差可能增加 |
| VQE 层数 | `RY + CX` 参数化结构重复层数 | 越深表达能力越强，但门数和优化难度增加 |
| 最大迭代数 | Powell 优化器的迭代预算 | 越大越可能收敛，但计算时间增加 |

当前固定配置包括：

- 映射方法：`jordan_wigner`；
- Ansatz：`hardware_efficient_ry_cx`；
- 初态：Hartree-Fock 占据态；
- 执行模式：`logical_virtual_qpu`。

参数化线路中的 `RY(theta)` 不是不能执行的抽象符号。VQE 优化完成后，`theta` 会被具体数值替换，最终 QASM 由 `X、RY(具体角度)、CX` 组成。

### 5.5 第三步：分区、芯片拓扑和路由

#### 分区数量与策略

用户选择 2 或 3 个分区。当前分区策略为 `sequential_greedy`。对于 `n` 个逻辑 Qubit 和 `k` 个分区，算法先使用整数除法得到每个分区的基础容量 `floor(n / k)`，再将余数 Qubit 逐一加入已有分区。

余数并不是固定加入第一个分区。算法只在仍处于基础容量的分区中选择，并综合以下因素评分：

- 余数 Qubit 与该分区已有 Qubit 的交互强度；
- 加入后对门时序连续性的割裂程度。

得分最高的可选分区接收该 Qubit，并且每个分区至多接收一个余数 Qubit。因此最终分区大小之差不超过 1，同时尽量减少跨分区门和时序割裂。

#### 分区间虚拟 QPU 拓扑

`inter_qpu_topology` 描述虚拟 QPU 之间的连接关系，例如：

```text
T1 --- T2 --- T3
```

它用于分区到虚拟节点的映射和跨分区通信，不表示芯片内部物理 Qubit 的连接。

#### 芯片内部物理耦合图

每颗虚拟 QPU 独立配置：

- `physical_qubit_count`：物理 Qubit 容量；
- `physical_coupling_map`：允许直接执行双比特门的物理边。

例如：

```text
q0 --- q1 --- q2 --- q3
```

如果线路要求执行 `CX(q0, q3)`，路由器不能直接执行，需要沿耦合图插入 SWAP。

#### 当前路由算法

当前配置为：

```text
initial_layout = identity
routing_method = shortest_path_swap
```

路由器按线路顺序处理每个芯片内 CX：

1. 根据当前布局找到控制和目标 Qubit 的物理位置；
2. 在无向物理耦合图上使用 BFS 查找最短路径；
3. 如果两者不相邻，沿路径依次插入 SWAP；
4. 更新 logical-to-physical 布局；
5. 在合法物理边上执行原 CX；
6. 保存路径、SWAP 位置和布局快照。

例如：

```text
路径：q0 -> q1 -> q2 -> q3

SWAP(q0, q1)
SWAP(q1, q2)
CX(q2, q3)
```

如果物理 Qubit 数量不足或耦合图断开，系统会在 `chip_topology_routing` 阶段返回 422 业务错误。

### 5.6 第四步：确认并执行

确认页汇总：

- 分子和原子数量；
- 电荷、自旋和基组；
- 活性空间和 VQE 预算；
- 分区数量；
- 分区间拓扑边；
- 每颗虚拟芯片的物理 Qubit 和耦合边；
- 布局和路由方法。

点击“开始计算”后，前端提交同步长任务。每个新任务生成独立 `Idempotency-Key`；网络重试复用同一个 Key，避免重复创建 Workflow。

| 1 | `input_validation` | 检查元素、坐标、电荷、自旋、基组和规模 | 阻止无效或超出能力边界的任务进入计算 |

| 6 | `vqe_optimization` | 优化 `X、RY、CX` 参数化线路 | 搜索活性空间内的近似低能量量子态 |

## 7. 模拟器到底如何执行线路

模拟器不会生成动画来代替计算，而是用经典线性代数逐门演算量子态。

以两个 Qubit 为例，状态向量包含四个复数振幅：

```text
[a_00, a_01, a_10, a_11]
```

初始 `|00>` 为：

```text
[1, 0, 0, 0]
```

执行门时：

- `X` 交换对应 Qubit 为 0 和 1 的振幅；
- `RY(theta)` 使用旋转矩阵更新对应振幅对；
- `CX` 在控制位为 1 时交换目标位振幅；
- `SWAP` 更新逻辑 Qubit 与物理 Qubit 的位置关系。

最终能量不是直接读取某个数组位置，而是逐项计算：

```text
expectation_i = <psi|P_i|psi>
contribution_i = coefficient_i * expectation_i
energy = sum(contribution_i)
```

## 8. 当前“分布式模拟”的准确含义

当前模拟器能够模拟分布式量子线路的执行语义：

- 使用真实分区方案；
- 使用虚拟 QPU 映射；
- 使用每颗芯片的物理耦合图；
- 插入并消费 SWAP；
- 识别跨分区 CX；
- 记录通信事件；
- 根据最终布局重新计算能量。

但它尚不是真正的多节点分布式状态向量模拟器。当前完整量子态仍保存在一个 Python 进程的 NumPy 全局张量中，没有发生：

- 多台服务器分别保存局部状态；
- 多进程或多节点并行执行；
- 真实网络张量传输；
- 真实通信带宽和延迟测量；
- 真实 QPU 噪声和退相干。

因此当前准确表述为：

> 虚拟节点逻辑分布式模拟，非真实 QPU。

它验证的是分布式编译和执行语义，而不是分布式硬件加速能力。

## 9. 如何阅读结果页

### 9.1 执行状态与质量状态

| 字段 | 含义 |
| --- | --- |
| `status=completed` | 十个阶段已执行完成，结果已持久化 |
| `validation_status=passed` | VQE 优化器报告收敛，质量检查通过 |
| `validation_status=needs_review` | 流程完成且结果保留，但 VQE 未收敛等问题需要复核 |
| `validation_issues` | 质量问题代码、阶段、迭代次数和说明 |

“执行完成”不等于“科学质量通过”。系统故意将两种状态分开。

### 9.2 电子结构和 Hamiltonian

| 结果 | 含义 |
| --- | --- |
| HF 能量 | PySCF 平均场近似总能量 |
| 活性电子/轨道 | 实际进入量子 Hamiltonian 的电子自由度 |
| Qubit 数 | 映射后的逻辑量子比特数量 |
| Pauli 项数 | Qubit Hamiltonian 中保留的算符项数量 |
| 截断误差估计 | 被 Pauli 系数阈值删除的系数绝对值总量估计 |

### 9.3 VQE 结果

结果页展示：

- 优化器名称和 SciPy 终止状态；
- 目标函数评估次数 `nfev`；
- 最佳迭代；
- 能量变化历史；
- 最佳参数；
- 最终 OpenQASM 线路。

`nfev` 是目标函数评估次数，不等同于优化器迭代上限，因此大于 `max_iterations` 不应直接解释为超限。

### 9.4 分区、路由和通信证据

| 结果 | 含义 |
| --- | --- |
| `partition_scheme` | 每个逻辑分区包含哪些 Qubit |
| `virtual_node_mapping` | 每个分区映射到哪颗虚拟 QPU |
| `partition_chip_routing` | 每颗芯片的耦合图和初始/最终布局 |
| `two_qubit_routing_evidence` | 每个芯片内 CX 的路径和 SWAP 证据 |
| `routed_execution_plan` | 模拟器实际消费的全局有序门序列 |
| `communication_events` | 每个跨分区 CX 的源、目标和门编号 |
| `actual_partition_consumption=true` | 模拟器确实使用了分区方案 |
| `actual_routed_plan_consumption=true` | 模拟器确实执行了路由后计划 |

SWAP 数量为 0 不代表没有执行路由阶段，只表示当前布局下所有芯片内 CX 已经位于合法耦合边上。

### 9.5 三种能量不要混淆

| 能量 | 来源 | 用途 |
| --- | --- | --- |
| `hf_energy_hartree` | PySCF Hartree-Fock | 经典平均场参考和 VQE 初态依据 |
| `unpartitioned_benchmark_energy_hartree` | 未分区 VQE 状态向量模拟 | 分布式一致性基准 |
| `distributed_simulation_energy_hartree` | 路由后计划的独立模拟 | 验证分区和路由后的结果 |

系统计算：

```text
absolute_error = abs(distributed_energy - unpartitioned_vqe_energy)
```

误差接近零说明分布式转换保持了原 VQE 线路的能量结果。它不等于 VQE 与真实实验能量之间的误差，也不证明量子优势。

当前统一小分子 Workflow 没有把 FCI 高精度经典参考接入最终结果。因此当前主要验证：

```text
Distributed VQE ≈ Unpartitioned VQE
```

尚未在该 Workflow 中直接验证：

```text
VQE ≈ FCI reference
```

## 10. 能力限制

当前 v2 Workflow 的主要限制为：

| 能力 | 当前限制 |
| --- | --- |
| 原子数量 | 最多 10 个 |
| 映射后逻辑 Qubit | 最多 12 个 |
| 活性空间轨道 | 最多 6 个 |
| 分区数量 | 2 或 3 |
| 分区策略 | `sequential_greedy` |
| 初始布局 | `identity` |
| 芯片内路由 | `shortest_path_swap` |
| 执行模式 | `logical_virtual_qpu` |
| 真实 QPU | 不支持，`is_real_qpu=false` |

状态向量模拟器保存 `2^n` 个复数振幅，内存和计算量随 Qubit 数指数增长。当前分区不会降低这一全局状态向量的渐近内存需求，因为所有分区仍由一个进程统一模拟。

## 11. 当前已经解决与尚未解决的问题

### 11.1 当前已经解决

- 从固定分子几何到 PySCF 电子结构的真实计算；
- 从电子积分到 Pauli Hamiltonian 的真实映射；
- 从 HF 初态到参数化 VQE 线路和优化能量；
- 线路均衡分区和虚拟 QPU 映射；
- 两类拓扑作用域的明确区分；
- 芯片内最短路径 SWAP 路由；
- 路由后执行计划的实际消费；
- 跨分区通信事件记录；
- 未分区与分布式能量的独立计算和一致性比较；
- Workflow 认证、持久化、幂等重试、详情恢复和历史查询。

### 11.2 当前尚未解决

- 真实 QPU 执行；
- 多机或多进程分布式状态向量计算；
- 真实量子网络协议和通信延迟；
- 噪声、门错误率和退相干模拟；
- 面向具体厂商芯片的原生门集编译；
- SABRE 等具有全局前瞻能力的高级路由；
- 自动几何优化、反应路径和过渡态搜索；
- FCI 参考与 VQE 科学精度误差的统一展示；
- 大分子和量子优势证明。

## 12. 推荐的系统表述

对外介绍时，推荐使用：

> 本平台面向分子电子基态能量计算，将固定分子结构转换为 VQE 量子线路，并在虚拟多 QPU 拓扑约束下完成线路分区、芯片映射、SWAP 路由和逻辑分布式模拟，通过独立能量重组验证分布式执行对原线路语义的保持。

不应使用以下未经当前能力支持的表述：

- 已在真实量子芯片上执行；
- 已实现多机分布式量子加速；
- 已突破经典状态向量模拟规模；
- 已获得真实实验级分子能量；
- 已证明量子优势。

## 13. 后续应用演进方向

在当前闭环基础上，可以按以下顺序扩展应用能力：

1. 接入小活性空间 FCI 参考，同时展示 `VQE-FCI` 和 `Distributed VQE-VQE` 两类误差；
2. 增加键长扫描和势能曲线，形成直观的化学应用案例；
3. 增加自动几何优化、结合能和反应能工作流；
4. 增加噪声模型和具体芯片原生门集；
5. 将全局状态张量拆分到多进程或多节点，记录真实通信量和耗时；
6. 在具备硬件条件时接入真实 QPU，并保持模拟与硬件结果的统一证据结构。
